## 2026-08-20 - SSRF Vulnerability via Replicate Input

**Vulnerability:** The `/api/generate` endpoint accepted an unvalidated `imageUrl` from the client request and passed it directly to the Replicate API as an image source. This constituted a Server-Side Request Forgery (SSRF) risk, where an attacker could provide URLs to internal systems or arbitrary external domains, potentially draining the application's Replicate API quota or exposing internal network information via error responses or processing latency.
**Learning:** External API wrappers must never implicitly trust client-provided URLs, even if the primary interaction is with a trusted third-party service (like Replicate). The vulnerability existed because the application assumed the client would only send URLs generated by the application's own Supabase storage flow.
**Prevention:** Implement strict domain allowlisting for all URLs passed to external APIs. In this case, validating that the parsed `imageUrl` hostname matches `process.env.NEXT_PUBLIC_SUPABASE_URL` or explicitly ends with `.supabase.co` ensures only expected and authorized domains can be used.
