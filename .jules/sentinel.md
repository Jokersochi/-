## 2024-11-11 - SSRF via Replicate API Input
**Vulnerability:** Server-Side Request Forgery (SSRF) and API quota drain vulnerability in `/api/generate.js` where user-controlled `imageUrl` was passed directly to the Replicate API without validation.
**Learning:** External API wrappers can be leveraged as SSRF proxies or cause financial drain if input URLs are not strictly validated against an expected list of trusted origins (like the specific Supabase project URL). Generic domain checks are insufficient because attackers can host malicious payloads on their own instances on the same SaaS platform.
**Prevention:** Always validate client-provided URLs using strict hostname matching against explicitly configured trusted origins (e.g., exact match with `process.env.NEXT_PUBLIC_SUPABASE_URL`). Implement this securely by checking for the environment variable first to prevent misconfiguration from being masked, and wrapping `new URL()` in a try-catch block to handle malformed input cleanly by returning a generic 400 Bad Request to avoid leaking validation details.
